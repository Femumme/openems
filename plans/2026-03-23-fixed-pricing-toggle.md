# Fixed Pricing: Add Enable/Disable Toggle — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an On/Off toggle to the `ctrlEvcsFixedPricing` modal so operators can disable the price override without deleting the component.

**Architecture:** Mirror the `ctrlFixActivePower0` pattern exactly — add a `Mode` enum (`MANUAL_ON`/`MANUAL_OFF`) to `Config.java`, gate `run()` on `config.mode()`, and wire the same `<oe-modal-buttons>` + `_PropertyMode` pattern in the Angular UI. No new channels are needed; `_PropertyMode` is auto-generated by `AbstractOpenemsComponent` from the new `Config.mode()` OSGi property.

**Tech Stack:** Java 21 / OSGi / JUnit 4 (backend); Angular 17 / Ionic / Karma+Jasmine (UI)

With:
```java

    this.config = config;
    if (this.config.mode() == Mode.MANUAL_ON) {
        this.log.info("Setting EVCS price override to {} EUR/kWh", roundPrice(this.config.priceEurPerKwh()));
    }
}
```

- [ ] **Step 2: Update `run()` — switch on `config.mode()`**

Replace current `run()`:
```java
@Override
public void run() throws OpenemsNamedException {
    if (this.config == null || !this.config.enabled()) {
        this._setActiveOverride(null);
        return;
    }
    var price = roundPrice(this.config.priceEurPerKwh());
    this.evcsPricing.setOverride(this.id(), price);
    this._setActiveOverride(price);
    this._setActiveCeiling(null);
    this._setActiveFloor(null);
}
```

With:
```java
@Override
public void run() throws OpenemsNamedException {
    if (this.config == null) {
        return;
    }
    switch (this.config.mode()) {
        case MANUAL_ON -> {
            var price = roundPrice(this.config.priceEurPerKwh());
            this.evcsPricing.setOverride(this.id(), price);
            this._setActiveOverride(price);
            this._setActiveCeiling(null);
            this._setActiveFloor(null);
        }
        case MANUAL_OFF -> {
            this.evcsPricing.removeOverride(this.id());
            this._setActiveOverride(null);
        }
    }
}
```

> **Note:** `MANUAL_OFF` calls `removeOverride` (not just clears the channel) so the pricing singleton no longer holds a stale override from this controller. `deactivate()` still calls `removeOverride` as a final cleanup.

## Appendix: Key Decisions

**Why `Mode` instead of a plain boolean?** The `_PropertyMode` channel (auto-generated by `AbstractOpenemsComponent`) exposes the current config value to the UI via WebSocket in real-time. A boolean `_PropertyEnabled` already exists via `config.enabled()` (the base-class `IS_ENABLED` channel), but it reflects the OSGi lifecycle state, not the operator's runtime intent. Using `Mode` gives us a distinct, named channel the UI can bind to with `CONVERT_MANUAL_ON_OFF`.

**Why `removeOverride` in `MANUAL_OFF`?** Simply clearing `_setActiveOverride(null)` only clears this controller's channel. `removeOverride(this.id())` removes the entry from the `EvcsPricing` singleton's map, so the pricing engine no longer considers this controller's override at all. Leaving a stale entry in the map would be incorrect.

**No i18n additions needed.** The toggle reuses `General.on` / `General.off` (already translated in all locales). The `EVCS.FixedPricing.price` and `.info` keys are untouched.
